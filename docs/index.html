Coral Hackathon Captain's Log

Reward triage before the agent acts.

Coral Reward Watchtower turns public prize, voucher, gift-card, and bounty leads into local SQL tables, so an agent can join candidates with evidence and next actions before creating noise.

View Repo Read The Build Guide

The Problem

Reward work is messy. Some leads are cash-only, token-based, already crowded, expired, or blocked by user-only steps like CLA signing. A coding agent should inspect that context before it comments, claims, or opens a pull request.

This project keeps the policy visible. Each candidate has a reward type, status, risk, verdict, score, evidence rows, and next-action owners. 

npm run demo
coral source lint .coral-local/reward-signals.yaml
coral source test reward_signals
coral sql "SELECT c.id, e.evidence_type, a.action_type
FROM reward_signals.candidates c
JOIN reward_signals.evidence e ON c.id = e.candidate_id
JOIN reward_signals.actions a ON c.id = a.candidate_id"

Why Coral

The JSONL files could be ranked by a script, but Coral makes them queryable and joinable by agents through the same local SQL surface they can use for richer sources later.

  • Three-table local JSONL source spec
  • Declared Coral validation queries
  • Candidate/evidence/action joins
  • Portable generated source file
  • Deterministic fallback ranker
  • No private account data in the repo
Actual reward receipt is not claimed. Legal agreements, contest registration, Discord, and social posting stay with the account owner.
